This release adds a Bitswap data plane, seed-only replication, verified SSH install and mesh updates, storage quotas, and a version-bound Agent Skills pack. It is the first stable tag after the `0.2.0-p2` pre-release.

## Added

- Bitswap data plane: resource-digest discovery still uses the trusted PTC mesh. Data is exchanged as 256KiB blocks through Boxo Bitswap, with relay, verification, a persistent cache, and replica failover.
- Large resources automatically use a multi-level Merkle index and are no longer capped at 10,000 blocks (~2.44GiB). Disk space, transfer timeouts, and relay connection quotas still apply. Small resources keep a v1 manifest; nodes that provide or receive large resources must be upgraded for v2 indexes.
- `ptc resources pull` writes a verified replica locally and announces the transport CID. The CID on the board is a transport manifest, not UnixFS.
- Seed-only jobs: a standalone `ptc/seed@v0` action fetches and publishes a named resource set without creating a workspace, running commands, or building a result package. It can be dispatched to a files-only node to add a disaster-recovery replica.
- `ptc install --ssh HOST` and `ptc update [--ssh HOST|--mesh]` download and verify official Release binaries, with rollback on a failed replace. Local `ptc update` writes `install.json` and restarts a running daemon (`--no-restart` skips that). `ptc update --mesh` rolls the same major version to recorded installs that allow remote updates; targets pull the binary with Bitswap. SSH supports Linux amd64/arm64 and Windows amd64, with strict host-key checking.
- Storage quotas and durable retention; seed cleanup protects active worktrees and stays within workspace quotas.
- Rate-limited manual discovery scans; scans cover the whole interface subnet and skip loopback.
- Version-bound Agent Skills pack at `skills/peer-task-control/`. `ptc skill sync`, and a successful `ptc update` or `ptc install`, write it to `~/.agents/skills/peer-task-control/`.
- Deployable `docker/` component, bilingual documentation, architecture figures, CI, and issue/PR templates.
- The Go module path is now `github.com/tigeregit/peer-task-control`, matching the GitHub URL.

## Fixed

- Local submits honor `--fetch-result`, and queue submits targeted at the local node are handled correctly.
- Rolling upgrades are safer and more observable; transport CIDs stay outside seeded content.
- Relay reservations are restored after reconnect; cancellations finalize consistently.
- Result-fetching JSON stays valid; run IDs no longer collide across nodes.
- Concurrent Bitswap exports reuse verified blocks; the scan host cache stays synchronized during config saves.

## Download and verify

The assets include Windows, Linux, and macOS amd64 / arm64 binaries (Windows is amd64), the skill text bound to this version, and the skill pack tarball. Verify against `SHA256SUMS` before you run anything. `ptc version` should be `0.3.0`.

Prefer the binaries on this page over `go install`, so the version is the stamped Release build.

## Known limits

- P1 remaining: UnixFS / filestore, CID / dataset input parsing, and block-cache GC. Directory-manifest pins exist; full pin management does not.
- P3: the official complete product UI (currently only the read-only board).
- P4 remaining: installing as an OS service; SSH install still does not write `install.json` on the remote.
- `ptc clean` applies only locally (no `ptc clean --node`).
- Dropping a follow connection does not automatically cancel a remote job; use an explicit `ptc cancel`.
